# 视觉设计规范

目标不是"加特效"，是**让一屏密集的信息在深色下依然分层清晰**。所有的发光、边框、动效都为这个目标服务；不服务这个目标的都砍掉。

## 1. 三条原则

**一、黑不是背景，是空间。** 底色 `#03060c` 近乎纯黑，但界面上叠着三层径向渐变（顶部冷蓝、左下、右下），让"黑"有纵深。面板是半透明毛玻璃浮在上面，不是贴在上面。

**二、光是信息，不是装饰。** 一个东西发光，只能因为它**重要**或**活着**。静态标签不发光；运行中的进度条发光；需要你处理的计数发光。滥用辉光的结果是全屏都在喊，等于全屏都没在喊。

**三、科技感来自排版纪律，不是来自特效。** 大写、宽字距、等宽的小标签（`.label`）承担了大部分"HUD 感"。它便宜、清晰、不抢戏，而且不需要引入任何 webfont。

## 2. 色板

```
底色    void      #03060c    整体背景
        deep      #060c16    次级背景
        panel     rgba(10,21,36,.55)   毛玻璃面板

主光    cyan      #35e8ff    主强调 · 运行中 · Agent 在线
        cyan-soft #7ef2ff    高亮态
        cyan-deep #0d6f86    次级 · 标签

语义    gold      #ffb347    Hermes 委派 · 待确认 · 警告
        lime      #6cf5a8    成功 · 完成
        magenta   #ff4d8d    失败 · 严重告警
        violet    #9d7bff    推理中

文字    ink       #dcecf9    正文
        ink-dim   #8fa9c0    次要
        ink-faint #536b83    标签 · 禁用

结构    hairline  rgba(120,200,255,.13)   一切边框
```

**金色专属于 Hermes 和"需要你"。** 这是刻意的语义绑定：视线扫过界面时，金色出现的地方就是委派出去的活或等你拍板的事。青色是 JARVIS 自己。

状态色通过 `--st-*` 令牌统一：任务卡边框、状态药丸、进度条、步骤圆点全部读同一组变量。改一处，全局一致。

## 3. 字体

不引入 webfont。中英文混排靠系统栈：

```css
--font-ui:   'Inter', -apple-system, 'Segoe UI',
             'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif;
--font-mono: 'JetBrains Mono', ui-monospace, SFMono-Regular, Menlo, monospace;
```

**所有数字用等宽 + `tabular-nums`。** 指标每秒刷新，比例字宽会让数字左右跳动，等宽消除这个抖动。

`.label` 是 10px / `0.18em` 字距 / 全大写 / 等宽。它出现在每个面板标题、每个指标名、每个时间戳上，是整套视觉里复用率最高的一个类。

## 4. 面板

```css
.panel {
  background: rgba(10, 21, 36, 0.55);
  border: 1px solid var(--hairline);
  border-radius: 14px;
  backdrop-filter: blur(18px) saturate(1.3);
  box-shadow: inset 0 1px 0 rgba(160,230,255,.06),   /* 顶部内高光 */
              0 18px 48px rgba(0,0,0,.45);           /* 外投影 */
}
```

顶部那道 1px 内高光是"玻璃感"的关键——它模拟边缘对天光的折射。去掉它，面板立刻变成一个平贴的方块。

`.bracketed` 在左上/右下加两个 14px 的直角括号。**这是全套里最强的 HUD 信号，所以只给面板用，绝不下放到卡片和按钮。** 用滥了就不是信号了。

## 5. 动效

| 名称 | 用途 | 时长 |
|---|---|---|
| `rise` | 新消息、新任务卡入场 | 300ms |
| `pulse` | 活跃指示点、流式光标 | 1.8s 循环 |
| `sweep` | 进度条上掠过的高光（仅运行中） | 1.9s 循环 |
| `spin` | 背景引导环 | 140s 循环 |
| `scan` | 全屏扫描线 | 9s 循环 |

缓动统一 `cubic-bezier(0.22, 1, 0.36, 1)`——快起慢收，有机械感但不生硬。

**扫描线只有一条。** 满屏 CRT 扫描线纹理是新手陷阱：它降低所有文字的可读性，换来的只是廉价的"赛博感"。一条 160px 高、透明度 0.028 的光带缓慢下移，是氛围；一整屏是噪声。

全局尊重 `prefers-reduced-motion`，命中时所有动画降到 0.01ms。

## 6. 布局

固定双栏 + 流动中栏：左 264px / 中 自适应 / 右 340px，间距 16px。

中栏内部纵向切分：数字人舞台 `flex: 1 1 52%`（最小 220px），对话流 `flex: 1 1 48%`，输入区固定高度。数字人始终占据视觉重心的上半部——它是这个应用的脸。

断点：

- `≤1280px` — 两侧栏收窄至 224 / 296
- `≤1040px` — 三栏塌成单列纵向滚动

## 7. 数字人的视觉调参

完整的层次拆解见 [DESIGN.md §5](./DESIGN.md#5-数字人)。这里只记调参上踩过的坑：

**加性混合下，平坦的内部 alpha 是灾难。** 第一版外壳用 `alpha = 0.16 + fresnel * 0.95`，那个 `0.16` 的常数项铺满整个圆面，和背后的粒子层、辉光层逐层相加，再被 bloom 一推，直接饱和成一个纯白球，所有结构都看不见了。

修正是两步：

1. 外壳内部压到近乎全透，把菲涅尔指数提到 3.2，让亮度只集中在掠射角的边缘：
   `alpha = 0.02 + pow(1 - dot(N,V), 3.2) * 0.88`
2. 亮度改由一个**独立的、有径向衰减的**辉光平面提供——双瓣衰减（`pow(1-d, 6)` 的紧核 + `pow(1-d, 2)*0.42` 的宽晕），保证没有硬边。

Bloom 阈值同步从 0.16 提到 0.30，只让最亮的边缘溢出，而不是整个画面。

结论是通用的：**发光效果的亮度应该来自一个有空间梯度的层，不是来自把某一层的不透明度调高。**
